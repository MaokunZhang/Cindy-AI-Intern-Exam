# B2：收工 Skill

## 1. 完整的 SKILL.md

文件：[skills/wrap-up/SKILL.md](../skills/wrap-up/SKILL.md)。它以“收工”“帮我收尾”等开发收尾请求触发，使用 Agent 已有的文件、Git 和命令执行能力，按 **测试 → 完整审阅 → 调试残留检查 → 简短摘要** 执行。

我把“每次都做得一样”落实为相同的步骤顺序、证据要求和完成标准：测试要有命令及退出码；审阅要覆盖本次范围内的所有文件；残留要逐项判断；摘要要报告结果与待处理项。不同项目可以使用不同测试命令，但不能省掉步骤或把未运行写成通过。

为明确“这次改了什么”，Skill 先确定本次任务基线，再覆盖已提交、暂存、未暂存与未跟踪文件。仅看一次 `git diff` 会漏掉暂存和已提交内容，仅看文件数量也代替不了逐段审阅。

## 2. 哪些固定，哪些交给 AI 判断？

| 环节 | 固定动作 | AI 判断 | 这样划分的原因 |
| --- | --- | --- | --- |
| 确定范围 | 读取项目规则；按用户范围、任务起点、工作区的优先级确定基线；列出各类改动 | 判断哪些文件属于本任务，哪些是其它人的已有改动 | 输入范围必须清楚，文件归属需要任务上下文 |
| 跑测试 | 按约定找到并执行真实命令；记录目录、命令、退出码和结果；失败后继续检查 | 项目未规定测试集时，依据改动模块和调用关系选择覆盖范围；解释失败 | 固定 `npm test` 无法适用于所有项目，执行与结果记录则可以统一 |
| 审阅改动 | 按文件逐段读完整 diff，新增文件读正文，覆盖删除和重命名 | 判断实现是否符合需求、异常分支和测试覆盖是否充分 | 阅读范围可以规定，正确性依赖代码语义 |
| 查调试残留 | 搜索调试线索，并人工看新增常量和临时分支；清理后复测和复查 | 区分临时输出、正式日志、CLI 输出和测试夹具；决定哪些可以清理 | `console.log` 或固定值只是线索，按关键词删除会破坏正常功能 |
| 输出摘要 | 使用固定字段报告范围、改动、测试、审阅、残留和待处理项 | 选择最关键的行为变化，解释问题影响 | 字段统一方便核对，内容需要结合本次工作提炼 |

测试失败不应让流程停在第一步：后面的审阅可能直接找到原因。清理调试代码后要重跑受影响测试，否则最终代码与“已通过”的测试结果不对应。没有自动化测试时如实记录，并列出替代检查和剩余验证事项。

“收工”只触发检查与必要的收尾修正。自动 commit、push、合并或发布不属于这四步；这些动作由当前任务另行明确。

## 3. 为什么适合 Skill，而不是插件？

这项需求是在约定**已有能力的使用方法**：什么时候跑测试、按什么范围看 diff、如何判断调试残留，以及怎样汇报。Agent 已经能读文件、运行命令和检查 Git，缺的是可复用的流程。一份 Skill 就能把步骤、判断标准和输出格式保存下来，也便于随项目规则调整。

本题没有新增外部数据接入、常驻界面或独立后台服务的需求。为此编写插件，还要维护运行入口、清单和宿主接口，却没有增加完成这四步所需的能力。因此选择 Skill 更直接。

如果以后需要一个持续展示多个仓库测试结果、保存历史并可点击操作的收工看板，插件可以提供界面与数据能力，Skill 继续定义检查流程。两者可以配合。

这个选择符合 Cindy 的[Core、Agent、Skill 与插件分工](https://github.com/makecindy/cindy/blob/f283ccebd3b9ef11d89807934b6ccafec6ef23a4/docs/product-rules/core-product-principles.md#5-coreagentskill-与插件的分工)：Skill 用于组织已有能力和反复出现的工作方法，插件用于专用能力、富交互与结构化状态。

## 4. 验证结果

- `quick_validate.py` 校验通过：名称、YAML 元信息和正文占位检查合格。
- 在独立临时 Git 仓库实际走查，覆盖已提交、暂存、未暂存和未跟踪文件，未改动答题项目源码。
- 第一轮测试 2/2 通过，但仍发现临时打印和新校验分支缺测试。清理临时打印、补充用例后 3/3 通过；CLI 正常输出与测试夹具保留。
- 第二轮故意把加法改成减法并加入 `debugger`，测试 1/3 通过、2/3 失败；流程继续读完整改动并定位错误与残留，结论为“待处理”。这验证了失败分支的执行方式。

这是编写过程中按 Skill 做的隔离走查，验证的是实际命令与决策过程；并非 Cindy 安装或多模型自动评测。详细记录见 [b2-verification.md](../notes/b2-verification.md)。
